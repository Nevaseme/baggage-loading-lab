# GPT-6 Astra向けプロジェクト指示の監査

確認日：2026-09-08。対象は指示書の改訂。アルゴリズム開発は一時停止を継続。

## 結論

旧 `AGENTS.md` は命名・禁止事項・モデル固定が中心で、最終目的、仮説の見直し、過去の計画との関係が不足していた。今回、目的と根拠に基づく判断を中心に再構成した。安全性と提出品質の条件は、変更ごとの作業手順から分離して維持した。

これは公式ガイドと保存証拠に基づく指示の改善であり、モデルの最高性能やPublicスコアの改善を実測した結果ではない。モデル・effortの実行設定も変更していない。

## 参照した公式資料

- [GPT-6 Astraのガイド](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra)：指示書・スキルの影響、自律性、委任、検証範囲を明確にする考え方を参照。
- [ChatGPT Learn: Prompting](https://learn.chatgpt.com/docs/prompting)：目的・必要な文脈・成果物・実害を防ぐ境界を中心にする考え方を参照。
- [Prompt engineering](https://developers.openai.com/api/docs/guides/prompt-engineering?api-mode=responses)：指示と文脈を区分する構成を参照。ユーザーの重複したURLはこの正規URLとして確認した。

以下の変更理由と受入条件は、このプロジェクトの依頼・記録に対する判断であり、OpenAIが本競技向けに指定したものではない。

## スキル・アプリ設定に残る境界

インストール済みSuperpowers 6.3.0の `brainstorming/SKILL.md` は限定変更にも設計承認を要求し、`receiving-code-review/SKILL.md` は会話表現の禁止例を多数含んでいた。`verification-before-completion/SKILL.md` にも強い停止表現がある。根拠確認という目的は有用だが、工程や表現の固定をそのまま常設のプロジェクト規則には取り込まなかった。

プラグインキャッシュは他プロジェクトにも影響し更新で置換されるため編集していない。プロジェクトでは最新ユーザー依頼と今回の運用方針を明確にし、実際にスキルが停止を要求した場合は該当ファイルと影響を説明する。アプリから注入される上位指示・既に読み込まれた文脈は、ディスク上の `AGENTS.md` 編集だけでは消去されない。設定・権限・認証情報は変更対象外とした。

## 確認方法と限界

文書の再読、リンク先の存在、残存する旧モデル固定の適用範囲、保護対象ファイルのSHA-256比較を実施した。変更対象8文書のローカルリンク19件に欠落なし。`submit/` のファイル、現行 `portal_reserved_scaffold_dag` パッケージ直下のファイル、外部評価表の計29ファイルは変更前後のハッシュが一致した。以下は静的な整合性レビュー項目であり、モデルを動かした行動評価ではない。

| 入力・状況 | 改訂後の期待動作 |
| --- | --- |
| 状況だけを聞かれた | 記録を確認して回答。開発開始や作業停止の操作を勝手に追加しない。 |
| 明確な範囲の修正を依頼された | 必要な確認と修正を実施し、追加承認は実際に必要な権限・判断に限る。 |
| Luna maxでは不向きな独立レビュー | 利用可能なモデル・effortを理由とともに選択する。 |
| 古い計画にSol必須・Phase停止と書いてある | 歴史的な文脈として読み、現在の依頼と採用判断を確認する。 |
| 単体テスト成功、物理比較は未完了 | テストの成功範囲だけ報告し、提出可能とは判定しない。 |
| 一時停止を依頼された | 進捗を保存し、管理下の稼働を停止・確認して引き継ぐ。 |

実際の有効性は、開発再開後の代表的な作業で、成果の正確性、不要な確認停止、再作業、所要時間・トークン使用を比較して判断する。今回の文書修正のために物理評価や追加のモデル実験は開始していない。
